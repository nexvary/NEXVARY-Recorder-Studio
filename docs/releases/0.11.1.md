# Guardian Studio 0.11.1 — settings and timer usability

A safety-timer screenshot from an Android 15/OPPO phone showed black dropdown text against a black popup. A shared spinner adapter now explicitly colors both selected and popup rows neon green, with a dark background and 52dp minimum rows. It also applies to safety, evidence, sensitivity and trusted-contact selections.

Settings now starts with four colored cards: family safety, language/appearance, optional account/sending, and the offline guide. Diagnostics are under an optional disclosure. Safety settings has a short setup path and individual pages for sharing, evidence, destination and device automation; saving one section merges only its fields into the latest configuration. Existing settings and consent remain preserved. Guardian PIN still protects settings and never blocks SOS.

The timer shows presets first, a custom-minute editor only for Custom, and a separate grace-period disclosure. Its main status focuses on state/time/sharing. Evidence tests and transport/device details are in an optional section. Account setup shows a single authentication step; login, signup, confirmation and password recovery no longer share a wall of simultaneous actions. Cloud provider fields stay under advanced connection settings. Local recording and SOS remain available without an account.

Version code 19; application ID and release key unchanged. Backend protocol and deployment package remain 0.11.0. No production service was deployed and no external alert is sent by UI tests.

Validation pending the release CI: unit tests, lint/static gates, backend checks and instrumentation on API 33/34/35. New regression cases cover actual green popup rows, custom timer recreation, optional settings navigation, independent section persistence, and staged authentication fields. Actual Arabic screenshots include the timer popup, settings landing, safety setup and sharing form. Physical Android 15/OPPO/ColorOS verification remains outstanding.
