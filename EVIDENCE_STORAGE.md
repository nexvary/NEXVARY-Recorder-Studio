# Evidence storage and integrity

Android stores the local emergency event/outbox in an atomic AES-GCM file backed by Android Keystore. Recordings remain app-specific local files. Each finalized file has SHA-256, eventId, segmentIndex, bytes, duration, device timestamp and an `EVENT_evidence_manifest.json` sidecar. The integrity hash detects later changes; it is not a legal certification or independently trusted timestamp. Device clock and camera encoder behavior require physical verification.

Emergency video targets 720p H.264 at 1 Mbps, 20 fps and optional mono AAC 48 kbps. Android chooses the nearest supported size and FPS. Segments close through MediaRecorder's next-output-file mechanism at a size target of about 30 seconds, avoiding a stop/reopen camera gap. Finalized segments upload asynchronously using WorkManager. The active final segment can be lost on force-stop or abrupt power loss; previously closed segments persist. No Android API guarantees camera survival after OEM process killing.

Backend `EvidenceStorageProvider`: uploadChunk, completeUpload, getSignedUrl, deleteEvidence. S3 implementation is wired to SAM and tested in mocked AWS. Wasabi adapter exists using the same private signed-URL protocol but is **not deployed or validated against a real Wasabi account**. Select SAM StorageProvider=WASABI and WasabiSecretArn holding bucket, endpoint, region, accessKey and secretKey. Configure Wasabi lifecycle/encryption/private-bucket independently. No real Wasabi deployment was tested. Do not claim the provider is live from the adapter alone. No storage key enters Android.

PUT links expire in 5 minutes. Email viewer links expire in 15 minutes; they can expose newly uploaded segments by refresh. Authenticated parent API can generate fresh 15-minute file links during the retention window. Expired links are refused; deleting evidence removes underlying objects. Never log tokens, URL query strings or file contents. S3 default encryption and TLS are enabled; private evidence is not end-to-end encrypted because authorized backend/provider processing can access it.

Local files are never automatically deleted by cloud retention. Account deletion removes cloud objects and account data; local files require the user's explicit deletion. Published account deletion web URL still needs hosting and verification before Google Play submission.
